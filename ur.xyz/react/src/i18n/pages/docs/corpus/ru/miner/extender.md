# Запуск экстендера

Экстендер — это ретранслятор, через который люди могут попасть в сеть из мест, где собственные серверы оператора заблокированы. Каждый майнер запускает его рядом со своим выходным узлом; по умолчанию он включён. Он работает, только если интернет может достучаться до вашего компьютера по TCP-порту 443. Если вы использовали установщик, пишите `urnetwork` везде, где на этой странице написано `provider`.

Экстендер — сторона каждого контракта, который через него проходит, поэтому он получает долю от каждого контракта, который обслуживает.

## Порты

Откройте эти порты для входящих подключений с любого адреса, по IPv4 и по IPv6:

| Порт | Протокол | Нужен | Для чего |
| --- | --- | --- | --- |
| 443 | TCP | Обязательно | Основной канал экстендера. Без него экстендер остаётся выключенным, а майнер пробует занять порт снова каждые 3 минуты. |
| 443 | UDP | Рекомендуется | Канал QUIC. |
| 4053 | UDP | Рекомендуется | Канал DNS. |
| 53 | UDP | По желанию | DNS на его стандартном порту. Если майнер не может его слушать, он теряет только этот один порт. |

Оператор проверяет TCP-порт 443 из интернета, прежде чем включить ваш экстендер в список. UDP-порты дают клиентам больше способов до него добраться.

Слушать TCP-порт 443 на компьютере может только одна программа. Когда на одном хосте работает несколько процессов майнера, например с `--all-operators`, первый занявший порт обслуживает экстендер для всего хоста, а другой берёт это на себя в течение 3 минут после его остановки. Веб-сервер или любая другая программа на порту 443 не даёт экстендеру включиться.

## Открытие портов

Между интернетом и майнером может быть три файрвола: собственный файрвол компьютера, файрвол облачного провайдера и домашний роутер. Каждый из них должен пропускать эти порты.

### Файрвол компьютера

С ufw (Ubuntu, Debian):

```bash
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw allow 4053/udp
```

С firewalld (Fedora, RHEL, Rocky, AlmaLinux):

```bash
sudo firewall-cmd --permanent --add-port=443/tcp --add-port=443/udp --add-port=4053/udp
sudo firewall-cmd --reload
```

Если у вас собственные правила nftables или iptables, добавьте разрешающие правила для этих портов в цепочку input — перед любым правилом, которое отбрасывает или отклоняет пакеты, — и сохраните их, чтобы они пережили перезагрузку.

Образы Ubuntu в Oracle Cloud поставляются с правилами iptables, которые отклоняют всё, кроме SSH. Вставьте разрешающие правила перед отклоняющим правилом, затем сохраните их:

```bash
sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 443 -j ACCEPT
sudo iptables -I INPUT -p udp --dport 4053 -j ACCEPT
sudo netfilter-persistent save
```

Для IPv6 выполните те же правила с `ip6tables`.

В macOS и Windows, если файрвол включён, разрешите входящие подключения для майнера (`provider` или `urnetwork` от установщика), когда он спросит.

### Облачные файрволы и группы безопасности

Перед облачным сервером обычно тоже стоит файрвол. Разрешите входящие TCP 443, UDP 443 и UDP 4053 с `0.0.0.0/0` и `::/0`:

- **AWS:** группа безопасности инстанса (правила для входящего трафика), а также сетевой ACL подсети, если вы его меняли.
- **Google Cloud:** правило файрвола VPC для входящего трафика, которое применяется к инстансу.
- **Azure:** группа сетевой безопасности на сетевом интерфейсе виртуальной машины или на её подсети.
- **Oracle Cloud:** список безопасности VCN или группа сетевой безопасности, а также правила iptables, описанные выше.
- **Hetzner Cloud:** Cloud Firewall, если он подключён к серверу.
- **DigitalOcean:** Cloud Firewall, если он подключён к Droplet.

### Домашние роутеры

Дома роутер не пропускает входящие подключения. В его настройках (часто они называются «проброс портов», «виртуальные серверы» или NAT) перенаправьте TCP 443, UDP 443 и UDP 4053 на компьютер, на котором работает майнер. Назначьте этому компьютеру постоянный адрес в вашей сети (резервирование DHCP), чтобы перенаправление и дальше указывало на него. Только один компьютер за публичным адресом IPv4 может получить порт 443.

Некоторые подключения перенаправить нельзя. Если интернет-адрес роутера (WAN) находится в диапазоне от `100.64.0.0` до `100.127.255.255` или не совпадает с адресом, под которым вас видят веб-сайты, ваш интернет-провайдер держит вас за NAT операторского уровня (CGNAT). Попросите у провайдера публичный адрес IPv4 или используйте IPv6.

Многие роутеры выдают каждому устройству публичный адрес IPv6, но блокируют входящие подключения IPv6. Разрешите входящие TCP 443, UDP 443 и UDP 4053 к этому компьютеру в файрволе IPv6 роутера.

### Docker

Майнеру в контейнере нужно опубликовать порты:

```bash
docker run -p 443:443/tcp -p 443:443/udp -p 4053:4053/udp …
```

Описанные выше файрволы по-прежнему действуют для хоста.

## Linux: разрешите майнеру слушать порт 443

Linux позволяет слушать порты ниже 1024 только привилегированным программам. Установщик и `provider service install` запускают майнер от имени вашего пользователя, поэтому его экстендер не может слушать TCP-порт 443 и остаётся выключенным. В журнале тогда появляется `tcp_443_permission_denied`. Майнер, который уже работает от root, например установленный через `sudo provider service install --system` или запущенный от root внутри контейнера, может. macOS и Windows позволяют слушать порт 443 любой программе, так что там ничего выдавать не нужно.

Решение — системная служба, которая запускает майнер от имени вашего пользователя с одной дополнительной привилегией: `CAP_NET_BIND_SERVICE`, которая позволяет программе слушать порты ниже 1024.

### С установщиком для Linux

Снова запустите установщик с `--system`, от имени пользователя, который майнит (не через `sudo`). Он один раз спросит ваш пароль `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/urnetwork/connect/main/scripts/Provider_Install_Linux.sh | sh -s -- --system
```

Существующую установку также можно переключить командой `urnet-tools reinstall --system`.

Установщик устанавливает `/etc/systemd/system/urnetwork.service`, который запускает майнер от вашего имени, останавливает и удаляет вашу собственную `urnetwork.service` и сохраняет ваш таймер обновлений. С этого момента `urnet-tools start`, `stop`, `restart`, `status`, `logs` и `uninstall` работают с системной службой, а `start`, `stop` и `uninstall` запрашивают `sudo`.

При запуске от root без пользовательского сеанса systemd (оболочка `sudo su`) установщик сам устанавливает системную службу.

### Через службу provider

```bash
sudo "$(command -v provider)" service install --system --as="$USER"
```

Полный путь указан потому, что `sudo` не ищет в `~/.local/bin`. Команда устанавливает `urnetwork-provider.service` как системную службу, которая запускает майнер от имени этого пользователя, с его бинарным файлом и его `~/.urnetwork`. Сначала она останавливает и удаляет собственную `provider service` этого пользователя, чтобы два майнера никогда не работали с одной идентичностью.

Обновления по-прежнему устанавливаются автоматически и выполняются от имени этого пользователя, а небольшой path-юнит, принадлежащий root, перезапускает службу после каждого обновления. `provider service status` показывает службу. Чтобы удалить её:

```bash
sudo "$(command -v provider)" service uninstall --system
```

Простая команда `sudo provider service install --system` без `--as` работает как раньше: она запускает майнер от root, с состоянием в `/var/lib/urnetwork`.

### Что выдаёт юнит

Юнит установщика для пользователя с именем `alice`:

```ini
[Unit]
Description=URnetwork Provider
Documentation=https://ur.xyz/docs/miner/extender
Wants=network-online.target
After=network-online.target

[Service]
User=alice
ExecStart="/home/alice/.local/share/urnetwork-provider/bin/urnetwork" provide
Restart=on-failure
RestartSec=30
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
NoNewPrivileges=yes

[Install]
WantedBy=multi-user.target
```

У юнита `provider service` та же строка `User=` и те же три строки о capabilities, с `ExecStart=<path>/provider start` и `Environment=URNETWORK_STATE_DIR=/home/<user>/.urnetwork`.

Всю выдачу привилегии составляют три строки:

- `AmbientCapabilities=CAP_NET_BIND_SERVICE` даёт майнеру эту одну привилегию.
- `CapabilityBoundingSet=CAP_NET_BIND_SERVICE` не даёт ему когда-либо получить какую-то другую.
- `NoNewPrivileges=yes` не даёт ни ему, ни всему, что он запускает, получить новые привилегии, например через программу с setuid.

Компромисс таков: пока служба работает, программа, которую она запускает, может слушать порты ниже 1024. Бинарный файл лежит в вашей папке, поэтому любой, кто может его заменить (вы или программа, работающая от вашего имени), может запустить под этим юнитом код, который слушает низкие порты. Никаких других привилегий этот код не получает: он не работает от root, `NoNewPrivileges` включён, а ограничивающий набор содержит только эту одну capability. Если на общем компьютере это неприемлемо, не используйте `--system`. Майнер по-прежнему майнит и без экстендера.

Другие способы выдать порт и почему майнер ими не пользуется:

- `setcap` на бинарном файле: файловые capabilities теряются каждый раз, когда обновление заменяет бинарный файл.
- Бинарный файл с setuid: это гораздо больше привилегий, чем нужно для одного порта.
- `net.ipv4.ip_unprivileged_port_start`: меняет правило для всех программ и всех пользователей на компьютере.

Чтобы вернуться к пользовательской службе: с установщиком выполните `urnet-tools uninstall`, затем установите снова без `--system` (ваша идентичность в `~/.urnetwork` сохраняется). С `provider service` выполните `sudo "$(command -v provider)" service uninstall --system`, затем `provider service install`.

## Проверка

```bash
provider status
provider doctor
```

В `provider status` есть строка **Extender**. В `provider doctor` есть строка **Inbound 443**: держит ли майнер TCP-порт 443 и результат его последней активации.

В журнале (`provider service logs --follow` или `urnet-tools logs`) запись `extender` сообщает, что не так, в поле `reason`, и как это исправить, в поле `guidance`:

| `reason` | Что это значит | Что делать |
| --- | --- | --- |
| `tcp_443_permission_denied` | Майнеру не разрешено слушать порт 443. | [Разрешите майнеру слушать порт 443](#linux-let-the-miner-listen-on-port-443). |
| `tcp_443_in_use` | TCP-порт 443 занят другой программой: другим процессом майнера или веб-сервером. | Порт может быть только у одной программы на компьютере. Майнер занимает порт в течение 3 минут после того, как тот освободится. |
| `tcp_443_bind_failed` | Не удалось слушать порт 443 по другой причине. | Прочитайте строки журнала вокруг этой записи. |
| `unreachable_on_tcp_443` | Майнер слушает, но тест оператора не смог достучаться до него из интернета. | [Откройте порты](#open-the-ports), затем перезапустите майнер. |

Экстендер, до которого интернет не может достучаться, пытается активироваться снова раз в сутки. Открыв порты, перезапустите майнер, чтобы попробовать сразу: `provider service restart` или, с установщиком, `urnet-tools restart`.
