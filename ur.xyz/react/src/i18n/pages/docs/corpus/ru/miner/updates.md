# Обновление майнера

Новые выпуски майнера исправляют проблемы и сохраняют совместимость вашего майнера с сетью, поэтому лучше работать на последнем. Если вы использовали [установщик](/docs/miner/install#the-installers) или позволили `provider setup` установить фоновую службу, делать ничего не нужно: майнер обновляется автоматически.

## Автоматические обновления (установщики)

Каждый установщик включает автоматические обновления, кроме Linux без пользовательского сеанса systemd и Windows, если вы устанавливаете определённую версию с `-Tag`. По умолчанию он проверяет наличие нового выпуска на [странице выпусков build](https://github.com/urnetwork/build/releases) примерно каждые 6 часов. Если новый выпуск есть, установщик скачивает его, сверяет с контрольной суммой SHA-256, которую для него указывает GitHub (выпуск без неё не устанавливается), убеждается, что новая программа запускается, и подменяет ею старую. Майнер, который работал, перезапускается на новой версии; остановленный вами остаётся остановленным. Если что-то идёт не так, продолжает работать старая версия. Ваша идентичность в `~/.urnetwork` не затрагивается, а ваши настройки обновлений и запуска сохраняются.

Как каждая система соблюдает расписание:

- **Linux:** таймер systemd, каждые 6 часов плюс случайная задержка до часа.
- **macOS:** агент launchd, который проверяет четыре раза в день в моменты, выбранные один раз для каждого Mac, и снова при входе в систему, так что Mac, который спал или был выключен, наверстывает пропущенное.
- **Windows:** средство обновления, которое скрыто запускается при входе в систему, просыпается каждый час и выполняет проверку, как только прошёл интервал, так что сон и перезагрузки не приводят к пропуску проверки.

Обновление заодно обновляет и сам `urnet-tools`. В Linux оно никогда не переводит вас на более старый выпуск.

Чтобы узнать, какая у вас версия и не вышла ли более новая, или чтобы сразу обновиться:

```bash
urnet-tools version
urnet-tools update
```

### Изменение или отключение автоматических обновлений

Автоматические обновления включены по умолчанию, и мы рекомендуем их не отключать. Чтобы узнать, включены ли они и как часто проверяют:

```bash
urnet-tools auto-update
```

Чтобы проверять реже, выберите `6h` (по умолчанию), `daily`, `weekly` или `monthly`. Включённые или выключенные обновления при этом такими и остаются:

```bash
urnet-tools auto-update --interval daily
```

Чтобы выключить их и включить снова:

```bash
urnet-tools auto-update off
urnet-tools auto-update on
```

Если автоматические обновления выключены, время от времени запускайте `urnet-tools update` сами. Ваш выбор сохраняется, когда вы обновляетесь или снова запускаете установщик. Чтобы с самого начала установить майнер с выключенными обновлениями, передайте `--no-auto-update` установщику для macOS или `-NoAutoUpdate` установщику для Windows. В Linux выполните `urnet-tools auto-update off` сразу после установки.

### Остаться на одной версии

Чтобы установить определённый выпуск, укажите его тег со страницы выпусков:

```bash
urnet-tools reinstall -t <version>
```

Затем выключите автоматические обновления командой `urnet-tools auto-update off`, иначе следующая проверка снова переведёт вас на последний выпуск.

## Автоматические обновления (служба provider)

[Фоновая служба](/docs/miner/run#with-provider-service), которую настраивает `provider setup` или `provider service install`, тоже поддерживает майнер в актуальном состоянии. Она проверяет [страницу выпусков build](https://github.com/urnetwork/build/releases) каждые 6 часов: в Linux — начиная через 15 минут после запуска компьютера, плюс случайная задержка до часа; в macOS — с момента входа в систему; в Windows — через 15 минут после входа в систему, плюс случайная задержка до часа. После выхода выпуска каждый майнер ждёт свою случайную часть из 16 часов, так что каждый майнер получает выпуск в течение суток, и при этом они не перезапускаются все одновременно.

Обновление сверяет загрузку с контрольной суммой SHA-256, которую для неё указывает GitHub (так обнаруживается повреждённая загрузка), сохраняет предыдущую программу рядом с новой и перезапускает службу. Если новая версия не поднимается в течение 10 минут (и не подключается снова, если до этого была подключена), возвращается предыдущая, а этот выпуск пропускается на неделю. Ваша идентичность в `~/.urnetwork` не затрагивается.

```bash
provider update --check    # is a newer release out?
provider update            # update now
provider update --status   # automatic update settings and the last check
```

Папка программы должна быть доступна для записи пользователю службы; `provider doctor` это проверяет. Майнер, настроенный установщиком, продолжает обновляться через `urnet-tools`, а `provider update` запускает его за вас.

### Отключение собственных обновлений майнера

Автоматические обновления включены по умолчанию, и мы рекомендуем их не отключать. Чтобы выключить их и включить снова:

```bash
provider update --off
provider update --on
```

Службу можно также установить с выключенными обновлениями: `URNETWORK_AUTO_UPDATE=0 provider service install`. Это не влияет на майнер, настроенный установщиком; там используйте `urnet-tools auto-update off`. Если обновления выключены, время от времени запускайте `provider update` сами.

## Без автоматических обновлений

[Сборка из исходного кода](/docs/miner/install#build-from-source) никогда не обновляется сама: соберите её заново. Майнер, который вы запускаете в терминале или под [собственной службой](/docs/miner/run#a-service-of-your-own), обновляется командой `provider update`; после этого перезапустите его.

Следите за новыми версиями на [странице выпусков](https://github.com/urnetwork/build/releases); GitHub может уведомлять вас о каждом выпуске. `provider --version` выводит вашу версию.
