# Как запустить майнер

> **Если фоновую службу вашего майнера настроил `provider setup` или `provider service install`, обновите майнер вручную один раз.** Начиная с выпуска 2026.10.22 такие майнеры не обновлялись сами — ни в Linux, ни в macOS, ни в Windows. Средство обновления майнера принимало версии вида `2026.10.27-1083160450`, а выпуски помечаются как `2026.10.27+1083160450`, поэтому каждый выпуск принимал себя за сборку для разработки:
>
> - `provider status` сообщает «development build, never updates itself».
> - `provider update` и автоматические обновления отказываются с сообщением «this is a development build … which never replaces itself with a release».
> - Проверка в течение 10 минут, которая откатывает новую версию, если та не подключается снова, ни разу не выполнялась.
>
> Исправление вошло в первый выпуск после 11 ноября 2026 года, и ваш майнер не может установить его сам. Когда этот выпуск выйдет, скачайте и распакуйте его, как описано в разделе [Загрузка вручную](/docs/miner/install#manual-download), и вместо установки запустите его обновление: `./linux/amd64/provider update` с вашей папкой из таблицы (с `sudo` впереди для системной службы) или в Windows `& "$env:TEMP\windows\$Arch\provider.exe" update`. Если набрать просто `provider update`, запустится ваш нынешний майнер, который по-прежнему отказывается. Обновление заменяет майнер, который запускает ваша служба, и перезапускает его.
>
> После этого обновления снова происходят автоматически: они распределяются примерно на 16 часов после каждого выпуска, с проверкой подключения в течение 10 минут, откатом и пропуском на 7 дней выпуска, который её не прошёл. Затем `provider status` показывает, что обновления автоматические или что у вас последняя версия.
>
> Если вы запускаете майнер сами, без этой службы, `provider update` тоже отказывается: установите новый выпуск, как описано в разделе [Загрузка вручную](/docs/miner/install#manual-download), и перезапустите майнер.
>
> Не затронуты: образ Docker, приложения и майнеры, настроенные установщиком (они обновляются через `urnet-tools`).

Майнер UR предоставляет ваше интернет-подключение сетевому оператору в качестве выходного узла. Валидаторы проверяют, что он действительно передаёт трафик, а Bittensor SN25 (netuid 25) платит за эту работу вознаграждения в токене подсети α под брендом $UR.

Удобнее приложение? Приложения URnetwork — простой способ майнить с телефона или компьютера: установите одно из них с [ur.io](https://ur.io), и оно будет майнить в фоне, с URnetwork в качестве оператора. Это руководство — о программе майнера, которая работает в Linux, macOS и Windows и может майнить для любого оператора.

## Как это работает

```text
your miner (provider)
  │ carries internet traffic for
  ↓
a network operator  ←─  validators
  │ pays its pool       measure it
  ↓ every epoch
your Bittensor coldkey (α, $UR)
```

Большинство майнеров присоединяются к **пулу** оператора. Собственная регистрация в Bittensor вам не нужна: вы входите в аккаунт у оператора, ваш майнер регистрирует себя как устройство, а вознаграждения пула выплачиваются на выбранный вами кошелёк Bittensor. Большие флоты могут вместо этого получить собственный UID майнера; см. [верхний уровень](/docs/miner/advanced#claim-your-own-miner-uid-head-tier).

## Что вам понадобится

- **Компьютер с Linux, macOS или Windows, который всегда в сети.** Подойдут домашний ПК, сервер или Raspberry Pi 2 и новее. В Windows майнер работает, пока вы вошли в систему.
- **Один стабильный публичный интернет-адрес на каждый майнер.** Чтобы запустить больше одного выходного узла с одного хоста, см. [Несколько выходных узлов на одном хосте](/docs/miner/advanced#several-exits-on-one-host).
- **Открытые порты для экстендера.** Майнер также запускает экстендер, который получает долю от каждого контракта, проходящего через него. Ему нужен входящий TCP-порт 443; рекомендуются UDP-порты 443 и 4053, а UDP 53 — по желанию. В Linux ему также нужно разрешение слушать порт 443. См. [Запуск экстендера](/docs/miner/extender).
- **Аккаунт у сетевого оператора.** Майнер использует оператора по умолчанию, `bringyour.com`, если вы не [выберете другого](/docs/miner/run#choose-an-operator). В своём аккаунте вы получите **код авторизации** (auth code), чтобы выполнить вход на майнере.
- **Адрес кошелька Bittensor (coldkey)** для ваших вознаграждений. Это адрес ss58, который начинается с `5`. Подписывать от его имени можно на другом устройстве; его секрет на майнере не нужен вовсе.

## Быстрый старт

Программа майнера называется `provider`. Установите её, запустите `provider setup` и проверяйте её состояние командой `provider status`.

### 1. Установка

Проще всего воспользоваться установщиком. Он помещает майнер в вашу домашнюю папку, запускает его в фоне и автоматически поддерживает в актуальном состоянии.

В **Linux**:

```bash
curl -fsSL https://raw.githubusercontent.com/urnetwork/connect/main/scripts/Provider_Install_Linux.sh | sh
```

В **macOS**:

```bash
curl -fsSL https://raw.githubusercontent.com/urnetwork/connect/main/scripts/Provider_Install_macOS.sh | sh
```

В **Windows**, в PowerShell (не от имени администратора):

```powershell
irm https://raw.githubusercontent.com/urnetwork/connect/main/scripts/Provider_Install_Win32.ps1 | iex
```

Затем откройте новый терминал. Установщик попросит код авторизации из вашего аккаунта у оператора (для оператора по умолчанию — из вашего аккаунта URnetwork на [ur.io](https://ur.io)), зарегистрирует это устройство и начнёт майнинг.

Установщик называет команду `urnetwork`, а не `provider`. Если вы им воспользовались, пишите `urnetwork` везде, где в этом руководстве написано `provider`, в том числе в командах, которые майнер выводит для копирования.

Чтобы установить майнер без установщика, см. [Загрузка вручную](/docs/miner/install#manual-download).

### 2. Запуск setup

```bash
provider setup
```

Команда проведёт вас через четыре шага; её можно прервать и запустить снова в любой момент — пройденные шаги сохраняются:

1. **Вход.** Вставьте код авторизации из аккаунта у оператора. Запрос скрывает то, что вы вставляете.
2. **Регистрация устройства.** Новое устройство получает собственную идентичность майнера, которая сохраняется в `~/.urnetwork`.
3. **Адрес для выплат.** Адрес вашего coldkey в Bittensor. Setup выведет короткое сообщение; подпишите его в приложении кошелька (Polkadot.js, Talisman или btcli) и вставьте подпись. Можно нажать Enter, чтобы пропустить этот шаг и [задать адрес позже](/docs/miner/rewards#set-your-payout-wallet).
4. **Постоянная работа.** Запускает майнер в фоне сейчас и снова после каждой перезагрузки (в Windows — при каждом входе в систему) и поддерживает его в актуальном состоянии.

Если вы использовали установщик, он уже выполнил вход, зарегистрировал это устройство и запускает майнер в фоне. Запустите `urnetwork setup --no-service`, чтобы добавить адрес для выплат; `--no-service` не даёт setup добавить второй фоновый майнер рядом с майнером установщика.

### 3. Проверка

```bash
provider status
```

Через минуту после запуска майнера в строках Miner, Signed in, Device и Connected должно стоять по ✓. Команда завершается с кодом 0, когда всё в порядке, 3 — когда устройству нужна настройка, и 4 — когда майнер не запущен или не подключён, так что её могут проверять и скрипты (`provider status --json` выводит подробности).

Когда что-то не так, `status` выводит команду, которую нужно выполнить дальше. `provider doctor` ищет причину: папку состояния, DNS, подключение, прокси, который инспектирует TLS, и часы. Журналы, остановка и запуск описаны на странице [Запуск и мониторинг](/docs/miner/run).

### 4. Резервная копия майнера

Скопируйте папку `~/.urnetwork` в надёжное личное место. В ней хранятся идентичность этого устройства и подписанная история вашего кошелька. Если вы её потеряете, устройство не восстановить, даже если вы по-прежнему можете войти в свой аккаунт. См. [Резервная копия майнера](/docs/miner/run#back-up-your-miner).

Вот и всё. Вознаграждения считаются за расчётную эпоху — в mainnet это около недели — и забираются после закрытия эпохи: см. [Получение оплаты](/docs/miner/rewards). Если что-то не сработало, см. [Устранение неполадок](/docs/miner/troubleshooting).

### Пошагово вместо setup

`provider setup` выполняет эти команды за вас. Чтобы сделать всё вручную:

```bash
provider login                    # paste the auth code when asked
provider start                    # the first start asks before registering this device
provider wallet challenge '<your coldkey ss58 address>'
provider service install          # in a second terminal, after Ctrl-C in the first
```

`provider wallet challenge` выводит сообщение для подписи; затем выполните команду `provider wallet set`, которую он выведет, со своей подписью. Подробности — на странице [Получение оплаты](/docs/miner/rewards#set-your-payout-wallet). `login`, `start` и `network` — те же команды, что и `auth`, `provide` и `choose_network`.
