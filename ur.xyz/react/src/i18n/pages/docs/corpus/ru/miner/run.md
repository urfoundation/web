# Запуск и мониторинг майнера

Эта страница предполагает, что вы [установили](/docs/miner/install) майнер и [настроили его](/docs/miner#2-run-setup). Если вы использовали установщик, пишите `urnetwork` везде, где на этой странице написано `provider`.

## Запуск и остановка

Чтобы майнить в терминале:

```bash
provider start
```

Команда показывает короткое живое представление (Connecting, Connected, ● Mining) и работает, пока вы не остановите её нажатием Ctrl-C. Подробный журнал пишется в `miner.log` в `~/.urnetwork`; добавьте `-v`, чтобы видеть его в терминале.

Первый запуск на новом устройстве спрашивает разрешения перед его регистрацией и сохраняет его идентичность в `~/.urnetwork`. Каждый следующий запуск использует эту идентичность. В скрипте, где некому ответить, добавьте `--allow-client-registration` к первому запуску. `provider provide` — та же команда с полным выводом журнала, для скриптов и служб.

Регистрируйте только действительно новое устройство. Регистрация никогда не заменяет идентичность, которая у майнера уже есть, но не удаляйте файлы, чтобы обойти ошибку об отсутствующей или несовпадающей идентичности: вместо этого см. [Устранение неполадок](/docs/miner/troubleshooting#the-miner-stops-straight-away).

Запускайте все команды майнера и фоновую службу от одного и того же пользователя. У каждого пользователя своя `~/.urnetwork`.

## Выбор оператора

Майнер обслуживает оператора по умолчанию, `bringyour.com` (`https://api.bringyour.com` и `wss://connect.bringyour.com`), если вы не выберете другого. Чтобы обслуживать другого оператора, выберите его **до** первого запуска, указав опубликованные им URL-адреса:

```bash
provider network use https://api.example.net wss://connect.example.net
provider network
```

URL-адреса API начинаются с `https://`, а URL-адреса подключения — с `wss://` (простые `http://` и `ws://` работают только с локальным тестовым сервером). `provider network` без аргументов показывает действующего оператора, а `provider network reset` возвращает оператора по умолчанию. Выбор сохраняется и действует для всех последующих команд. Затем выполните `provider setup` или `provider login` с кодом авторизации от этого оператора.

Смена оператора не переносит уже зарегистрированное устройство к новому оператору. Держите для каждого оператора отдельное состояние и отдельный аккаунт. Чтобы обслуживать сразу всех операторов из опубликованного списка, см. [Майнинг для всех операторов из списка](/docs/miner/advanced#mine-every-listed-operator).

## Работа в фоне

### С установщиком

[Установщики](/docs/miner/install#the-installers) уже запускают майнер в фоне: пользовательской службой systemd в Linux (или, при установке с `--system`, [системной службой, которая работает от вашего имени](/docs/miner/extender#with-the-linux-installer)), агентом launchd в macOS и ярлыками автозагрузки в Windows. Управляйте им через `urnet-tools`:

```bash
urnet-tools start          # start it (no error if it's already running)
urnet-tools status         # version, signed in, running, updates; exits 3 when it isn't running
urnet-tools logs           # follow its log; Ctrl-C to stop reading
urnet-tools restart
urnet-tools stop           # stop it until you start it again, restart (Linux) or log in again (macOS, Windows)
urnet-tools auto-update off   # turn automatic updates off; `on` turns them back on
```

Если при установке вы пропустили вход, выполните `urnetwork login`, затем `urnet-tools start`: это зарегистрирует устройство и запустит майнер. О том, как работают автоматические обновления, см. [Обновления](/docs/miner/updates).

В Linux и Windows с майнером установщика работают и `provider service start`, `stop`, `status` и `logs`.

Майнер сам запускается при загрузке в Linux (когда включён lingering; установщик пытается его включить), при входе в систему в macOS и при входе в систему в Windows, где он также **останавливается, когда вы выходите из системы**. `urnet-tools auto-start off` отключает автоматический запуск, а `urnet-tools auto-start on` снова его включает.

Если майнер аварийно завершается, systemd в Linux перезапускает его через 30 секунд, а launchd в macOS — через 60. В Windows остановившийся майнер остаётся остановленным, пока вы не выполните `urnet-tools start` или снова не войдёте в систему. Майнер, который завершился штатно, например потому что устройство [не зарегистрировано](/docs/miner/troubleshooting#the-miner-stops-straight-away), остаётся остановленным: `urnet-tools status` тогда сообщает, что он не запущен.

### Через службу provider

`provider setup` предлагает настроить это. Чтобы сделать это самостоятельно, остановите майнер, если он работает в терминале, а затем:

```bash
provider service install
```

Команда запускает майнер сейчас, снова запускает его сама, перезапускает при аварийном завершении и каждые 6 часов проверяет [обновления](/docs/miner/updates):

- **Linux:** пользовательская служба systemd, `urnetwork-provider.service`, которая запускается при загрузке. Она включает lingering, чтобы служба продолжала работать после выхода из системы, или выводит команду `sudo loginctl enable-linger`, которую нужно выполнить.
- **macOS:** агент launchd, который запускается при входе в систему. Его журнал — `service.log` в `~/.urnetwork`.
- **Windows:** приложение автозагрузки, которое скрыто запускает майнер при входе в Windows и останавливает его при выходе. Права администратора ему не нужны. Его журнал — `service.log` в `%USERPROFILE%\.urnetwork`.

Чтобы управлять ею:

```bash
provider service status
provider service logs --follow   # Ctrl-C to stop reading
provider service restart
provider service stop
provider service uninstall       # your sign-in and identity are kept
```

На сервере или чтобы майнить для всех пользователей компьютера в Linux или macOS, используйте общесистемную службу, работающую от root, с состоянием в `/var/lib/urnetwork`: `sudo provider setup --system` или `sudo provider service install --system`. Добавляйте `--system` к остальным командам `provider service`, чтобы управлять ею. В Windows общесистемной службы нет. В Linux пользовательская служба не может слушать TCP-порт 443 для экстендера майнера; `sudo "$(command -v provider)" service install --system --as="$USER"` запускает майнер как системную службу, которая остаётся вашим пользователем и может слушать этот порт. См. [Разрешите майнеру слушать порт 443](/docs/miner/extender#linux-let-the-miner-listen-on-port-443). Для множества машин `provider setup --yes --auth-code-file=<path>` выполняет настройку без вопросов; шаг с выплатами он пропускает, поэтому затем [задайте кошелёк для выплат](/docs/miner/rewards#set-your-payout-wallet).

В Linux и Windows `provider service install` не добавит второй майнер рядом с майнером установщика. В macOS он не видит агента установщика, поэтому если вы использовали установщик для macOS, продолжайте пользоваться `urnet-tools` и не устанавливайте вторую службу.

### Собственная служба

Чтобы запускать майнер со своими параметрами или без systemd и launchd, запускайте `provider provide` под своим менеджером служб, в `tmux` или `screen`. Например, в Linux создайте `~/.config/systemd/user/ur-miner.service`:

```ini
[Unit]
Description=UR miner

[Service]
ExecStart=%h/.local/bin/provider provide
Restart=on-failure
RestartPreventExitStatus=3
RestartSec=10
UMask=0077

[Install]
WantedBy=default.target
```

Остановите майнер, если он запущен, затем включите службу и следите за её журналом:

```bash
systemctl --user daemon-reload
systemctl --user enable --now ur-miner.service
journalctl --user -u ur-miner.service -f
```

Чтобы служба продолжала работать после выхода из системы, один раз включите lingering: `sudo loginctl enable-linger "$USER"`. Не добавляйте `--allow-client-registration` в команду службы, чтобы при отсутствии идентичности служба останавливалась, а не регистрировала незаметно для вас новое устройство. Не запускайте одновременно эту службу и `provider service`. Собственная служба не обновляет майнер; см. [Обновления](/docs/miner/updates#without-automatic-updates).

## Проверка работы

### Status и doctor

```bash
provider status
```

По одной строке о майнере, входе, регистрации устройства, подключении и обновлениях, а также команда, которую нужно выполнить дальше, если что-то не так. Команда завершается с кодом 0, когда всё в порядке, 3 — когда устройству нужна настройка, и 4 — когда майнер не запущен или не подключён. `provider status --json` выводит то же самое для скриптов и мониторинга.

```bash
provider doctor
```

Ищет, почему майнер не может войти или подключиться: закрыта ли папка состояния от других, DNS, подключение к оператору, прокси или файрвол, инспектирующий TLS, часы и могут ли устанавливаться обновления. Для каждой найденной проблемы называет способ её устранить.

### Журнал

`provider start` пишет журнал в `miner.log` в `~/.urnetwork`. Для фонового майнера используйте `provider service logs --follow`, а при установке через установщик — `urnet-tools logs`.

Майнер пишет много строк журнала в нескольких форматах; большинство из них — рутина. Хорошие признаки:

- `"event":"identity_available"`: майнер нашёл или создал идентичность этого устройства.
- Майнер продолжает работать. Если он сам останавливается через несколько секунд, что-то не так, даже если завершение выглядит штатным.

Тревожные признаки:

- Строка JSON с `"event":"startup_recovery_required"`, после чего программа завершается: см. [Устранение неполадок](/docs/miner/troubleshooting#the-miner-stops-straight-away).
- Слово `refused`, повторяющееся каждые несколько секунд: оператор не принимает подключение. См. [Устранение неполадок](/docs/miner/troubleshooting#the-log-keeps-saying-refused).

Добавьте `-v` или, для ещё большей детализации, `-vv`, чтобы видеть больше подробностей.

### Страница состояния

Майнер может отдавать небольшую страницу состояния в формате JSON. По умолчанию она выключена; включите её параметром `--port`:

```bash
provider provide --port=8080
```

Затем на той же машине:

```bash
curl -s http://127.0.0.1:8080/
```

Она показывает `version` майнера (у сборок выпусков она есть), имя хоста `host` и раздел `diagnostics` с последним результатом входа (`authentication`), `keys`, `extender` и `runtime`. Поле верхнего уровня `"status":"ok"` означает лишь, что процесс майнера запущен; оно не означает, что майнер подключён или зарабатывает, поэтому читайте и `diagnostics`.

Страница состояния слушает на всех сетевых интерфейсах, а не только на локальном. Закройте этот порт в файрволе или разрешите доступ только из своей сети мониторинга.

## Полезные параметры

| Параметр | Что он делает |
| --- | --- |
| `--max-memory=1gib` | Мягкая цель по памяти, в байтах или с `b`, `kib`, `mib` или `gib`. Без него майнер выбирает цель сам, исходя из памяти компьютера. |
| `-v`, `-vv` | Больше подробностей в журнале. |
| `--port=<port>` | Отдавать [страницу состояния](#the-status-page) на этом порту. `0`, значение по умолчанию, выключает её. |

`provider auth-provide` выполняет вход и запуск одной командой. Новому устройству по-прежнему нужен `--allow-client-registration`. Все параметры — в `provider help all` и в [Справочнике](/docs/miner/reference).

## Резервная копия майнера

Всё, что делает это устройство *вашим* майнером, находится в `~/.urnetwork`: его ключ идентичности, его регистрация, его вход и подписанная история вашего кошелька. Если вы потеряете эту папку, устройство не восстановить, даже если вы по-прежнему можете войти в свой аккаунт.

- Остановите майнер (или его службу), прежде чем копировать папку, чтобы ничего не оказалось записанным наполовину.
- Копируйте папку **целиком**, храните копию в надёжном личном месте и восстанавливайте её как единое целое.
- Никогда не запускайте одновременно две копии одной и той же папки — ни на одной машине, ни на двух.

В [Справочнике](/docs/miner/reference#files-the-miner-keeps) перечислен каждый файл в этой папке.
