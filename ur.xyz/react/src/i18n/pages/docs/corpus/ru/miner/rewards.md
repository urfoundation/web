# Получение оплаты за майнинг

Ваш майнер зарабатывает за трафик, который он передаёт. Эта страница описывает три части получения оплаты: как сообщить оператору, на какой кошелёк Bittensor платить ([задайте кошелёк для выплат](#set-your-payout-wallet)), [как считаются вознаграждения](#how-rewards-are-counted) и [как их забрать](#claim-your-rewards).

Если вы использовали установщик, пишите `urnetwork` везде, где на этой странице написано `provider`.

## Задайте кошелёк для выплат

Вознаграждения поступают на **coldkey** Bittensor — адрес ss58, который начинается с `5`. Вы доказываете, что coldkey ваш, подписывая им короткое заявление. Оператор хранит это подписанное заявление для данного устройства, поэтому одного адреса кошелька, сохранённого в профиле вашего аккаунта, недостаточно.

Проще всего воспользоваться шагом выплат в [`provider setup`](/docs/miner#2-run-setup): он выводит сообщение, вы подписываете его в приложении кошелька и вставляете подпись. Позже можно снова запустить `provider setup` только ради этого шага; если вы использовали установщик, запустите `urnetwork setup --no-service`. Команды ниже делают то же самое вручную.

Задавайте кошелёк **после** первого запуска устройства (`provider setup` или первого `provider start`), потому что в заявлении указано устройство, которое регистрирует этот запуск. До этого `wallet challenge` и `wallet set` завершаются ошибкой `claim/wallet credential not ready at …/.provider.jwt`.

### Подпись в приложении кошелька (рекомендуется)

Так секрет вашего coldkey не попадает на майнер. Сначала запросите заявление:

```bash
provider wallet challenge '<coldkey_ss58>'
```

Подпишите выведенное заявление в точности как есть этим coldkey в кошельке, который умеет подписывать необработанные сообщения с sr25519, например в [polkadot.js Apps](https://polkadot.js.org/apps/#/signing) (Developer → Sign and verify) с аккаунтом из расширения Polkadot.js. Затем выполните команду `provider wallet set`, которую вывел challenge, со своей подписью. (Если вы использовали установщик, замените `provider` в её начале на `urnetwork`.) Она выглядит так:

```bash
provider wallet set '<coldkey_ss58>' \
  --message='<exact printed statement>' \
  --signature='0x<64-byte sr25519 signature>'
```

Какой должна быть подпись:

- Над заявлением в точности как оно выведено, как текст UTF-8 с окончаниями строк LF и без лишнего перевода строки в конце, подписанным sr25519 в контексте подписи `substrate`. В `--message` буквальное `\n` обозначает перевод строки.
- Принимается и `signRaw` из расширения Polkadot с типом `bytes`, которое оборачивает заявление в `<Bytes>...</Bytes>`.
- Отправьте подпись в течение времени, которое выводит challenge, обычно пяти минут.

Выведенная команда сохраняет оператора и устройство, которые вы используете, поэтому копируйте её, а не набирайте свою.

### Подпись с файлом seed на майнере

Если вы сознательно храните seed своего coldkey на компьютере майнера, майнер может сам получить и подписать заявление:

```bash
provider wallet set '<coldkey_ss58>' \
  --coldkey_seed_file=/absolute/private/coldkey.seed
```

Файл должен уже существовать, принадлежать вам, быть закрытым от других (например, с правами `0600`) и не иметь символических ссылок в пути. Он содержит необработанный 32-байтный мини-секрет sr25519 или то же самое в виде 64 шестнадцатеричных символов с необязательным `0x`. Это не мнемоническая фраза. Команда отклоняет seed, который не соответствует адресу, а сам seed никогда не покидает ваш компьютер.

Кошелёк можно также задать при запуске майнера: `provider provide --wallet='<coldkey_ss58>' --coldkey_seed_file=/absolute/private/coldkey.seed`. Если это не удастся, майнер запишет ошибку в журнал и продолжит работать, поэтому проверьте журнал, прежде чем на это полагаться.

### Когда кошелёк начинает зарабатывать

Вознаграждения считаются по **эпохам**. Новая настройка кошелька начинает действовать со **следующей** эпохи и действует 65 536 эпох, поэтому задавайте её до эпохи, в которой хотите зарабатывать, и продлевайте до того, как срок истечёт. Она никогда не меняет, куда идут более ранние вознаграждения. Чтобы вместо этого выбрать точный диапазон, передайте и `--wallet-from-epoch=<epoch>`, и `--wallet-through-epoch=<epoch>` командам `wallet challenge` и `wallet set`; самую раннюю принимаемую эпоху всё равно определяет оператор.

Майнер хранит каждое подписанное заявление в `.provider.jwt.wallet-consent/history.json` в `~/.urnetwork`. Храните его вместе со своей [резервной копией](/docs/miner/run#back-up-your-miner). Если отправка заявления прервалась, повторный запуск той же команды отправит то же подписанное заявление, даже если seed на компьютере уже нет.

Каждому устройству, которое должно зарабатывать, нужен свой подписанный кошелёк; несколько устройств могут использовать один и тот же coldkey. Для дополнительных выходных узлов на одном хосте выбирайте каждый через `--provider-jwt`: см. [Несколько выходных узлов на одном хосте](/docs/miner/advanced#several-exits-on-one-host). Чтобы подписать один раз для всех операторов из списка, см. [Одна подпись для всех операторов из списка](/docs/miner/advanced#sign-once-for-every-listed-operator).

## Как считаются вознаграждения

Вознаграждения пула зависят от трафика, который ваш майнер передал до конца, и от того, насколько надёжным он оказался при измерениях. Оператор записывает выполненную работу на ваше устройство и платит на кошелёк, подписанный для этой эпохи. **Платный и бесплатный трафик одинакового объёма приносят одинаковый зачёт.** Балансы аккаунтов, резервирования, оплата подписок и незавершённые контракты не являются доказательством работы.

Доля каждого устройства в пуле пропорциональна:

```text
completed usage bytes × reliability
reliability = confirmations / max(assignments, reliability_a_min)
```

Чтобы получить оплату за эпоху, устройству нужно ненулевое завершённое использование, не меньше требуемого числа проверок, хотя бы одно подтверждение, подписанный кошелёк для этой эпохи и отсутствие активной привязки к верхнему уровню. Устройства, которые платят на один и тот же coldkey, складываются в одну выплату. Начиная с эпохи перехода на расчёты v2, пул делится только по завершённому использованию, без коэффициента надёжности и минимума, на счета — по одному на каждый coldkey для выплат, — которые никогда не сгорают (см. [Litepaper](/docs/litepaper)).

Валидаторы самостоятельно измеряют качество маршрутизации и взвешивают пулы операторов и флоты верхнего уровня. Майнерам платят **momentum**: долю эмиссии подсети для майнеров, которая расходуется сейчас на работу сети и делится между уровнем пулов и верхним уровнем согласно политике. Momentum составляет 10 %; текущее значение указано в опубликованной политике вашего оператора. [Network Capacity Reserve](/reserve), аккаунт `ur-reserve`, получает остальное: эмиссия майнеров × (1 − momentum). Её доля не фиксирована: она уменьшается по мере роста momentum. Momentum — это доля эмиссии, а не фиксированная цена за байт; фактический заработок показывают опубликованная политика вашего оператора и файлы выплат. Резерв отделён от залогового обеспечения заявок в расчётном хранилище.

Расчётную эпоху задают развёрнутые контракты и политика. В mainnet это 50 400 блоков, около семи дней при 12 секундах на блок. После закрытия эпохи её корень выплат фиксируется и финализируется до открытия заявок, поэтому недавнюю работу нельзя забрать сразу. Когда это станет возможно, подскажут `claim_open_block`, который выводит команда получения, и опубликованные окна развёртывания вашего оператора.

## Получение вознаграждений

Заявка получает ваше доказательство у оператора, проверяет его и отправляет в расчётное хранилище, которое платит на ваш coldkey. Вам понадобятся опубликованные данные развёртывания вашего оператора: его конечная точка EVM RPC, адрес расчётного хранилища и ID цепочки (964 в mainnet). Сам по себе вход и майнинг не означают, что вознаграждения подсети у оператора активны; об этом говорит его опубликованное развёртывание.

### 1. Проверьте заявку

```bash
provider claim --epoch='<settlement_epoch>' --rpc='https://<evm-json-rpc>'
```

Используйте конечную точку EVM RPC вашего оператора; `--rpc` можно повторить для резервных, они пробуются по порядку. Майнер проверяет доказательство и корень выплат и выводит `epoch`, `no_id`, `coldkey`, `share_bps`, корни выплат, `contract` хранилища, `claim_open_block` и данные заявки. Сверьте coldkey, контракт и ID цепочки с опубликованным развёртыванием вашего оператора. Несовпадение доказательства или корня завершается ошибкой: разберитесь с этим вместе с оператором до отправки.

Без `--epoch` майнер выбирает эпоху перед текущей. Эта эпоха может ещё ждать финализации своего корня, так что заявка может быть ещё не открыта. Более старые невостребованные эпохи указывайте явно.

### 2. Отправьте её

Для отправки нужен ключ **relayer** для EVM: отдельный ключ secp256k1 с небольшим количеством TAO для оплаты газа в сети Subtensor EVM. Он только платит комиссию; вознаграждение всё равно идёт на coldkey из доказательства. Поместите его 32-байтный шестнадцатеричный ключ в закрытый файл, затем попробуйте без отправки:

```bash
provider claim --epoch='<settlement_epoch>' \
  --rpc='https://<evm-json-rpc>' \
  --key_file=/absolute/private/relayer.key --dry-run
```

Затем отправьте:

```bash
provider claim --epoch='<settlement_epoch>' \
  --rpc='https://<evm-json-rpc>' \
  --key_file=/absolute/private/relayer.key
```

`--key_file` требует `--rpc`. Отправить ваше доказательство может любой relayer со средствами: он не может изменить coldkey или получить вознаграждение. Вознаграждение приходит как нативный стейк α на ваш coldkey. Seed coldkey для получения не нужен.

### 3. Прочитайте результат

| Событие | Значение |
| --- | --- |
| `Claimed` | Хранилище приняло заявку и зачислило сумму на ваш coldkey. Само по себе это не доказывает перевод. |
| `ClaimPaid` | Зачисленная сумма переведена на ваш coldkey. |
| `ClaimPaymentDeferred` | Зачисленная сумма пока остаётся в хранилище, например потому что она ниже минимума для перевода, цена недоступна или перевод не удался. |

Отложенная сумма не сгорает. Более поздняя заявка выплатит накопленную сумму, как только оплата станет возможной, и любой может повторить её через метод хранилища `withdrawClaimCredit(bytes32 coldkey)`; его вызывает `snclaim withdraw --vault=v1` (с `--coldkey`, `--contract`, `--rpc` и `--key_file`). Повторная отправка уже принятой заявки — это не вывод средств, и она завершается ошибкой как уже полученная.

Забирайте вознаграждения до истечения права на них. В mainnet это восемь эпох плюс одна льготная эпоха; после этого невостребованные вознаграждения могут вернуться в пул того же оператора. Истечение срока не отменяет уже принятые суммы. Начиная с эпохи перехода на расчёты v2, счета никогда не сгорают.

Чтобы забирать вознаграждения автоматически или отправлять заявки с другого компьютера, не с майнера, см. [Для опытных](/docs/miner/advanced#claim-automatically).
