# إبقاء المُعدِّن محدَّثًا

تُصلح النسخ الجديدة من المُعدِّن المشكلات وتُبقي مُعدِّنك متوافقًا مع الشبكة، لذا من الأفضل تشغيل أحدثها. إن استخدمت [مُثبِّتًا](/docs/miner/install#the-installers)، أو تركت `provider setup` يثبّت خدمة في الخلفية، فلا شيء عليك فعله: يُحدَّث المُعدِّن تلقائيًا.

## التحديثات التلقائية (المُثبِّتات)

يفعّل كل مُثبِّت التحديثات التلقائية، إلا على Linux دون جلسة مستخدم لـ systemd، وعلى Windows عندما تثبّت نسخة محددة باستخدام `-Tag`. افتراضيًا يتحقق من وجود نسخة أحدث على [صفحة نسخ build](https://github.com/urnetwork/build/releases) كل 6 ساعات تقريبًا. وعندما توجد، ينزّلها، ويتحقق منها مقابل قيمة SHA-256 التي يدرجها GitHub لها (ولا تُثبَّت نسخة بلا هذه القيمة)، ويتأكد من أن البرنامج الجديد يعمل، ثم يستبدل به القديم. المُعدِّن الذي كان يعمل يُعاد تشغيله على النسخة الجديدة؛ أما الذي أوقفته فيبقى متوقفًا. وإن فشل أي شيء، تواصل النسخة القديمة العمل. لا تُمس هويتك في `~/.urnetwork`، وتُحفظ إعدادات التحديث والبدء الخاصة بك.

كيف يلتزم كل نظام بالجدول:

- **Linux:** مؤقّت systemd، كل 6 ساعات مع تأخير عشوائي يصل إلى ساعة.
- **macOS:** وكيل launchd يتحقق أربع مرات يوميًا في أوقات تُختار مرة واحدة لكل جهاز Mac، ومرة أخرى عند تسجيل دخولك، فيلحق جهاز Mac الذي كان نائمًا أو مطفأً بما فاته.
- **Windows:** أداة تحديث تبدأ مخفية عند تسجيل دخولك، وتستيقظ كل ساعة وتتحقق بمجرد انقضاء الفاصل الزمني، فلا يتسبب السكون وإعادة التشغيل في تخطي أي تحقق.

يحدّث التحديث أيضًا `urnet-tools` نفسه. وعلى Linux لا ينقلك أبدًا إلى نسخة أقدم.

لمعرفة النسخة التي لديك، وهل صدرت نسخة أحدث، أو للتحديث فورًا:

```bash
urnet-tools version
urnet-tools update
```

### تغيير التحديثات التلقائية أو إيقافها

التحديثات التلقائية مفعّلة افتراضيًا، ونوصي بإبقائها مفعّلة. لمعرفة هل هي مفعّلة، وكم مرة تتحقق:

```bash
urnet-tools auto-update
```

للتحقق بوتيرة أقل، اختر `6h` (الافتراضي) أو `daily` أو `weekly` أو `monthly`. يُبقي هذا التحديثات مفعّلة أو موقوفة كما هي:

```bash
urnet-tools auto-update --interval daily
```

لإيقافها، ثم إعادة تفعيلها:

```bash
urnet-tools auto-update off
urnet-tools auto-update on
```

عندما تكون التحديثات التلقائية موقوفة، شغّل `urnet-tools update` بنفسك من حين إلى آخر. يُحفظ اختيارك عند التحديث أو عند تشغيل المُثبِّت مجددًا. للتثبيت والتحديثات موقوفة منذ البداية، مرّر `--no-auto-update` إلى مُثبِّت macOS، أو `-NoAutoUpdate` إلى مُثبِّت Windows. وعلى Linux، شغّل `urnet-tools auto-update off` مباشرة بعد التثبيت.

### البقاء على نسخة واحدة

لتثبيت نسخة محددة، أعطِ وسمها من صفحة النسخ:

```bash
urnet-tools reinstall -t <version>
```

ثم أوقف التحديثات التلقائية باستخدام `urnet-tools auto-update off`، وإلا فسينقلك التحقق التالي إلى أحدث نسخة مجددًا.

## التحديثات التلقائية (خدمة provider)

> **لم تثبّت هذه التحديثات أي نسخة منذ 2026.10.22.** بمجرد صدور أول نسخة بعد 11 نوفمبر 2026، حدّث يدويًا مرة واحدة، كما يشرح الإشعار في أعلى صفحة [كيف تشغّل مُعدِّنًا](/docs/miner). ومن ثم تعمل كما هو موصوف هنا.

تُبقي [الخدمة في الخلفية](/docs/miner/run#with-provider-service) التي يُعدّها `provider setup` أو `provider service install` المُعدِّن محدَّثًا أيضًا. تتحقق من [صفحة نسخ build](https://github.com/urnetwork/build/releases) كل 6 ساعات: على Linux بدءًا من 15 دقيقة بعد تشغيل الحاسوب، مع تأخير عشوائي يصل إلى ساعة؛ وعلى macOS منذ تسجيل دخولك؛ وعلى Windows بدءًا من 15 دقيقة بعد تسجيل دخولك، مع تأخير عشوائي يصل إلى ساعة. بعد صدور نسخة، ينتظر كل مُعدِّن حصته العشوائية الخاصة من 16 ساعة، فتصل النسخة إلى كل مُعدِّن خلال يوم دون أن يُعاد تشغيل المُعدِّنات كلها في الوقت نفسه.

يتحقق التحديث من التنزيل مقابل قيمة SHA-256 التي يدرجها GitHub له (وهذا يكشف التنزيل التالف)، ويحتفظ بالبرنامج السابق بجانب الجديد، ويعيد تشغيل الخدمة. إن لم تعد النسخة الجديدة إلى العمل خلال 10 دقائق (ومتصلة مجددًا، إن كانت متصلة من قبل)، تُعاد النسخة السابقة، وتُتخطّى تلك النسخة لمدة أسبوع. لا تُمس هويتك في `~/.urnetwork`.

```bash
provider update --check    # is a newer release out?
provider update            # update now
provider update --status   # automatic update settings and the last check
```

يجب أن يكون مجلد البرنامج قابلًا للكتابة من قِبل مستخدم الخدمة؛ ويتحقق `provider doctor` من ذلك. يواصل المُعدِّن الذي أعدّه مُثبِّت التحديث عبر `urnet-tools`، ويشغّله `provider update` نيابة عنك.

### إيقاف التحديثات الذاتية للمُعدِّن

التحديثات التلقائية مفعّلة افتراضيًا، ونوصي بإبقائها مفعّلة. لإيقافها، ثم إعادة تفعيلها:

```bash
provider update --off
provider update --on
```

يمكنك أيضًا تثبيت الخدمة والتحديثات موقوفة: `URNETWORK_AUTO_UPDATE=0 provider service install`. لا يؤثر ذلك في مُعدِّن أعدّه مُثبِّت؛ استخدم هناك `urnet-tools auto-update off`. وعندما تكون التحديثات موقوفة، شغّل `provider update` بنفسك من حين إلى آخر.

## من دون تحديثات تلقائية

[البناء من المصدر](/docs/miner/install#build-from-source) لا يحدّث نفسه أبدًا: ابنِه من جديد. أما المُعدِّن الذي تشغّله في طرفية، أو ضمن [خدمة خاصة بك](/docs/miner/run#a-service-of-your-own)، فيُحدَّث باستخدام `provider update`؛ ثم أعد تشغيله.

راقب [صفحة النسخ](https://github.com/urnetwork/build/releases) لمعرفة النسخ الجديدة؛ ويمكن لـ GitHub إشعارك بكل نسخة. يطبع `provider --version` النسخة التي لديك.
